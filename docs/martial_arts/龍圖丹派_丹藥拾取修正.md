# 龍圖丹派｜丹藥拾取修正與煉丹指令立即執行（2026-10-19～20）

**狀態：三項修正都已在 GitHub main（`daemon/misc/heat_commands.c` 的 `put_limit()`、`daemon/misc/heat_d.c` 的 `handles()` 與 `enqueue()`）。本檔原存於 claude.ai「龍圖設定」專案，2026-11-06 移入 `docs/`。**

## 一、撿不起丹藥（2026-10-19）

### 症狀
地上的丹藥成品（如金鎖固精丸）撿不起來，訊息為「<角色名>似乎裝不下了。」；一般藥材（龍涎草、山豬果）正常。

### 原因
`get` 撿丹藥成品時改走煉丹系統 `daemon/misc/heat_commands.c` 的 `put_limit()`。它用 `query_max_encumbrance()` 判斷空間，但這是容器用的上限，角色身上永遠是 0；角色的真正上限是 `query_strength("carriage")`（見 `std/char.c` 的 `receive_object()`）。結果所有丹藥成品（以及配方）對玩家一律判定裝不下。

### 修正（只改 `put_limit()`）
目的地是角色時用 `query_strength("carriage")`，失敗訊息改為原版的「XX現在對你來說太重了。」；容器、丹鼎的判斷不變。

### 驗證（測試環境：同版 mudlib + Neolith 實際執行）
- 修正前：山豬果可撿，金鎖固精丸出現「小明似乎裝不下了。」（重現成功）
- 修正後：金鎖固精丸、烏心丹可撿，且會與身上同種丹藥合併
- 超重仍會擋下：兩萬粒養心丹 →「養心丹現在對你來說太重了。」

## 三、煉丹指令全部立即執行（2026-10-20，使用者決定）

### 原本
get／drop／put（丹爐、丹鼎、松柴、配方、焦灰及丹爐／丹鼎內的東西）、ignite／extinguish、prepare mixture，全部經 `heat_d.c` 的 `enqueue()` 排進佇列，下一次心跳（約 2 秒）才執行，訊息出現在提示符號 `>` 之後。

### 修正（只改 `enqueue()`）
改為當下執行：與心跳相同的包裝（`begin_operation` → `heat_commands->execute` → `end_operation`），執行後做與心跳結尾相同的收尾（`flush_holder`／`flush_furnace`／`flush_wood`／`flush_scents`）。若在心跳處理途中被呼叫，仍排到下一次心跳，避免重入。

### 為什麼安全
每次心跳結尾都會把到期事件（火候、燒焦、燃料、燙傷）結算完，兩次心跳之間狀態一致；`before_take()` 也會在取出前先結算。時鐘（各種 phase 的累加）仍只由心跳推進，所以火候速度、燃料消耗、燙傷間隔都不變。

### 驗證（真實時間完整流程，一般玩家角色）
| 步驟 | 結果 |
|---|---|
| 配方放進丹鼎、丟丹爐、丹鼎放進丹爐、點火、松柴放進丹爐 | 每步 0.1 秒內回應 |
| 藥香（烏心丹、25 根松柴） | 第 138 秒出現（設計推算約 2 分鐘） |
| 取出丹鼎、取出配方、prepare mixture | 立即；「你將五份烏心丹配方製作成五粒烏心丹。」 |
| 取出松柴、熄火 | 立即；松柴 25 → 18 根，燃料消耗正常 |
| 手持燃燒松柴 | 第 9 秒出現燙傷訊息（5 次心跳） |
| 煉丹錯誤紀錄 `log/heat_b` | 無 |
