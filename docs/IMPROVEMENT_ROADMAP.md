# 專案改善建議清單

整理自 2026-10 的維運與開發經驗（使用者要求保留，2026-10-24）。每做完一項，在「狀態」欄註記日期。
做任何一項之前，先寫規劃文件給使用者確認（`CLAUDE.md`「工作方式」）。

## 一、穩定與安全（建議最先做）

| # | 建議 | 為什麼 | 狀態 |
|---|---|---|---|
| 1 | 開 PR 時自動檢查：開遊戲、登入一次、跑現有測試，有錯不准合併（GitHub Actions） | 曾有語法錯誤會讓全服登不進去，目前沒有任何上線前把關 | 2026-10-24 完成（`docs/CI_AUTO_CHECK.md`；「不准合併」待 wolfer168 在 GitHub 打開） |
| 2 | 修好長期失敗的測試（test_v25） | 測試一直紅燈，自動檢查就失去參考價值 | 2026-10-24 完成（test_v25、test_v30、test_v33 一併修好） |
| 3 | 玩家資料備份每天複製到主機以外的地方（Oracle 雲端儲存或自己的電腦） | 現在備份和遊戲在同一台主機，主機壞掉會一起沒了 | |
| 4 | 紀錄檔自動輪替（logrotate），只留最近幾天 | 曾經橋接紀錄 690 MB、debug.log 39 MB 才被發現 | |
| 5 | 監控與通知：CPU 長時間滿載、一天重開多次、硬碟快滿時寄信或推播 | 之前都是玩家回報才知道出事 | |
| 6 | 主機加裝 fail2ban，自動封鎖一直亂試 SSH 登入的 IP | 紀錄裡每分鐘都有陌生 IP 在猜帳號 | |
| 7 | 從根本修掉遊戲伺服器的兩個漏洞：連線失敗收不掉（造成 CPU 滿載）、收到關閉訊號當成當機 | 目前是繞過去（停用帳號查詢、當機時存檔），之後做 zMUD 入口等網路功能可能再踩到 | |
| 8 | 定期安排整台主機重開，套用系統核心（kernel）更新 | 自動更新不會重開主機，核心更新會一直擱著 | |

## 二、工作流程

| # | 建議 | 為什麼 | 狀態 |
|---|---|---|---|
| 9 | 讓 Claude 直接把 PR 開到 wolfer168（擁有者安裝 Claude GitHub App 並給寫入權限），所有人以 wolfer168 為主 | 現在要開兩次 PR，容易漏合併；其他協作者直接改 wolfer168，兩邊常不同步、出現衝突 | 2026-10-24 完成（已確認可直接在 wolfer168 開 PR，`CLAUDE.md`「開 PR」流程已改） |
| 10 | 一個主題一個 session；結束前把重點寫進 `docs/`，新 session 讀文件接手；避免多個 session 同時改同一個檔案 | 省用量，也避免 `CLAUDE.md`、說明檔互相衝突 | |
| 11 | `update.sh hot` 免重開模式：自動判斷這次改動要不要重開，列出要在遊戲裡 `update` 的檔案 | 很多更新其實不用讓玩家斷線 | |
| 12 | 主機另開一個測試服（同一台主機、不同連線埠），巫師先試玩再更新正式服 | 武功、NPC 現在是上線後才由玩家實際體驗 | |
| 13 | 找回兩個沒上傳成功的舊 session 的成果（10/14「合併 es2-webmud 分支至 main」的缺字 Excel 與 commit、9/25「種族設定與複雜機制討論」） | 推送被拒絕，內容只存在那兩個 session 裡，時間久了可能遺失 | |
| 17 | 倉庫瘦身：移除 Neolith 編譯中間檔（只保留 Windows 單機測試用的 `neolith.exe`）、舊版報告與過時交接筆記 | 約 500 個每台機器都能重新編譯的中間檔混在 git 裡，讓倉庫變大、不好找檔案 | 2026-10-28 完成（`.gitignore` 已排除；`HANDOFF.md` 移到 `docs/archive/`） |

## 建議順序

1. 先做 #1（自動檢查）與 #3（異地備份）：出事代價最大，做起來不複雜。
2. 接著 #4、#5、#6：主機維運一次處理完。
3. 再做 #9：流程簡化後，之後每一項都會更順。
4. 其餘依需要安排。
