# 同 IP 在線人數限制（討論稿）

狀態：**已製作（2026-10-20）**。
使用者已決定：採「做法二」（把真實 IP 傳進遊戲，由遊戲判斷），並要有巫師在遊戲內調整上限的指令。

## 一、目標

- 同一個 IP 同時在遊戲世界裡的角色數有上限，超過就不能再進入，用來抑制多開。
- 巫師在遊戲內用指令隨時調整上限，不用改程式、不用重開。
- 順便讓遊戲原本跟 IP 有關、目前失效的功能恢復作用。

## 二、現況與問題

```
瀏覽器 ──https──▶ Caddy（https 轉送）──▶ 網頁橋接程式 ──telnet──▶ 遊戲 4001
```

- 遊戲看到的每個玩家位址都是 `127.0.0.1`（主機自己），分不出誰是誰。
- 因此下列原本就有的功能目前等於沒作用：
  - 封鎖 IP（`ENABLE_BAN_SITE`）
  - 同一 IP 短時間內建立太多角色的限制（`ENABLE_ANTISPAM`）
  - 頻道「某某由某處連線進入」顯示的位址、`finger` 顯示的上線位址
- 網頁橋接程式拿得到真實 IP：Caddy 會把它放在 `X-Forwarded-For` 標頭裡。

## 三、做法

### 1. 橋接程式把真實 IP 告訴遊戲（`server/index.js`）

- 每條連線一接上遊戲，橋接程式先送一行玩家看不到的暗號：
  `@@REALIP <密碼> <真實IP>`
- **密碼**：一串隨機字元，存在主機上的檔案 `mudlib/adm/etc/bridge_secret`（不放進 git）。
  部署腳本第一次執行時自動產生；橋接程式與遊戲都讀這個檔案。
- **防假冒**：
  - 玩家自己輸入以 `@@REALIP` 開頭的內容，橋接程式直接丟掉，不送進遊戲。
  - 密碼不符的暗號，遊戲一律忽略。
- 真實 IP 的取法：連線來源是本機（Caddy）時，才採用 `X-Forwarded-For` 的最後一個位址；
  直接連到橋接程式的（例如本機測試）就用連線本身的位址。

### 2. 遊戲記住每條連線的真實 IP

- 新增一個小程式 `adm/daemons/realipd.c`：記錄「哪一條連線 → 真實 IP」。
  以連線的本機埠號區分；角色從登入畫面換到遊戲身體時是同一條連線，所以不會跟丟。
- 登入程式 `adm/daemons/logind.c` 在等玩家輸入代號時，若收到合法暗號就交給 realipd 記下，
  畫面上不顯示任何東西，繼續等玩家輸入代號。
- 在共用函式（simul_efun）裡把 `query_ip_number()`、`query_ip_name()` 改成「有真實 IP 就回傳真實 IP」。
  這樣封鎖 IP、防洗角色、頻道位址、`finger` 等**現有功能不用逐一修改就會恢復作用**。

### 3. 進入世界時檢查人數（`adm/daemons/logind.c`）

- 時機：玩家輸入密碼正確、角色要進入世界的那一刻（`enter_world`）。
- 算法：計算目前世界裡「真實 IP 相同」的玩家角色數。
  - **斷線但身體還留在世界裡的角色也算**（否則可以登入一隻、斷線、再登入下一隻）。
  - **斷線重連回自己原本的角色不算新的一個**，一定可以連回去。
  - **巫師不受限制，也不計入人數。**
- 已達上限：顯示提示後中斷連線，不建立身體、不影響已在線上的角色。
- 調低上限時，已經在線上超過的人**不會被踢**，只影響之後新進入的人。

### 4. 巫師指令 `iplimit`（新增 `cmds/adm/iplimit.c`，只有 admin 能用）

| 用法 | 作用 |
|---|---|
| `iplimit` | 顯示目前上限、白名單，以及目前有多個角色在線的 IP 與角色名單 |
| `iplimit list` | 一次列出所有在線玩家（含斷線留在世界的），依 IP 分組，標出已超過上限的 IP |
| `iplimit <人數>` | 設定同一 IP 最多幾個角色同時在線，例如 `iplimit 3` |
| `iplimit 0` | 不限制 |
| `iplimit allow <IP> <人數>` | 白名單：指定某個 IP 的上限（例如家裡兩人一起玩、網咖） |
| `iplimit remove <IP>` | 移除白名單 |

- 設定存檔在 `data/iplimit.o`，重開伺服器後仍保留。
- 每次修改都寫一行紀錄到 `log/static/IPLIMIT`（誰、什麼時候、改成多少）。
- 預設上限：**3**。
- 誰能用：**admin**。

### 5. 被擋下時的提示（江湖說法，不提數字、不提指令）

「同一處來的俠客已然滿座，請稍候再來。」

## 五、限制與風險

- **共用 IP 會被一起算**：家人、室友、網咖、學校，特別是手機行動網路（電信業者常讓大量用戶共用 IP）。
  上限不宜太低，並用白名單處理。
- **擋不住換 IP 的人**：手機熱點、VPN 都能換 IP，這個功能只能提高多開門檻。
- **admin 登入檢查不變**：原本「admin 只能從主機本機登入」的檢查改用連線本身的位址判斷，行為與以前相同（經網頁登入的 admin 照常可以進入）。
- **realipd 出錯時一律放行**：登入程式呼叫 realipd 都包在錯誤保護裡，就算它出錯也不會擋住所有人登入。
- **隱私**：系統頻道「某某由某處連線進入」與 `finger` 會開始顯示真實 IP；系統頻道只有巫師看得到。
- **IPv6**：同一戶的裝置可能拿到不同的 IPv6 位址，等於各算各的。IPv6 以前 64 位元視為同一戶，合併計算（白名單也以同一戶為單位）。
- **Caddy 以外的連線方式**：之後若做 zMUD／Telnet 入口，同樣經過橋接程式，會一併送出真實 IP，規則一致。

## 六、測試方式

1. 本機架遊戲與橋接程式，模擬不同 IP 的連線（直接送帶不同 `X-Forwarded-For` 的請求）。
2. 同一 IP 登入到上限後，下一個被擋、看到提示；不同 IP 不受影響。
3. 斷線重連回自己角色不被擋；斷線留在世界的角色有計入。
4. 巫師不受限；`iplimit` 各用法正確，重開後設定仍在。
5. 玩家自己輸入 `@@REALIP ...` 無效；密碼錯誤的暗號無效。
6. `finger`、頻道上線訊息顯示真實位址；封鎖 IP 生效。
7. 既有測試結果不變。

## 七、已確認事項（2026-10-20）

1. 預設上限 3 人。
2. `iplimit` 只給 admin 使用。
3. 要白名單。
4. 提示用「同一處來的俠客已然滿座，請稍候再來。」
5. IPv6 以同一戶（前 64 位元）合併計算。
6. 要能一次檢查所有人：`iplimit list`。
