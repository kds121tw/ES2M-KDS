# zMUD／Telnet 連線規劃（討論稿）

狀態：**討論稿，尚未製作**。確認後才開始寫程式。

## 一、目標

讓玩家除了網頁之外，也能用下面兩種方式連進同一個遊戲世界：

1. **舊版 zMUD 4.62**（只看得懂 Big5 繁體中文）。
2. **支援 UTF-8 的新式 MUD 用戶端**（Mudlet、MUSHclient、CMUD、PuTTY 等）。

不同連線方式的玩家在同一個世界裡一起玩：看得到彼此、可以組隊、交易、PK，頻道互通，同一個角色可以換不同方式登入。

## 二、現況

```
玩家瀏覽器 ──網頁(https)──▶ 網頁橋接程式 server/index.js ──telnet──▶ 遊戲伺服器 Neolith(4001)
```

- 遊戲伺服器本來就是 telnet 伺服器，編碼是 UTF-8，在主機的 4001 埠。
- 4001 只給主機自己的網頁橋接程式用；主機防火牆與 Oracle 安全清單都沒有對外開放。
- repo 已有 `zmud_big5_bridge.ps1`（Windows PowerShell 版 Big5 轉碼），是給「在自家 Windows 電腦架伺服器」用的，雲端的 Linux 主機無法執行。

## 三、規劃後的架構

```
網頁玩家      ──https──────────▶ 網頁橋接程式 ─┐
zMUD 4.62    ──telnet:4002(Big5)─▶ Big5 轉碼  ─┼─▶ 遊戲伺服器 Neolith(4001，仍只給主機內部用)
UTF-8 用戶端 ──telnet:4003──────▶ 直接轉接   ─┘
```

三個入口都放在同一個橋接程式 `server/index.js` 裡，最後都連到同一台遊戲伺服器。
4001 維持不對外，所有外部連線都先經過橋接程式，方便控管連線數量、日後加記錄或擋惡意連線。

| 入口 | 埠號 | 給誰 | 編碼 |
|---|---|---|---|
| 網頁 | 照舊（https） | 瀏覽器 | UTF-8 |
| zMUD | 4002 | zMUD 4.62 | Big5 ↔ UTF-8 轉碼 |
| Telnet | 4003 | Mudlet、MUSHclient、CMUD、PuTTY | UTF-8，原樣轉接 |

## 四、要做的事

### 1. Big5 轉碼入口（4002）

- 在 `server/index.js` 多開一個 4002 埠：每個 zMUD 連線各自連一條到遊戲伺服器 4001。
- 遊戲 → 玩家：UTF-8 轉成 Big5。玩家 → 遊戲：Big5 轉成 UTF-8。
- 傳統 MUD 的控制訊號（telnet 的 IAC 協商，`0xFF` 開頭的位元組）**原樣傳遞，不轉碼**。
- 一個中文字可能被切成兩段送達，要先暫存不完整的字，等湊齊再轉。
- Big5 沒有的字或符號換成「?」。
- 轉碼用 `iconv-lite` 套件（Node 內建只能解 Big5、不能轉成 Big5），加進 `server/package.json`。
- 參考現有 `zmud_big5_bridge.ps1` 的處理邏輯。

### 2. UTF-8 轉接入口（4003）

- 多開一個 4003 埠，原樣轉接到 4001，不轉碼。

### 3. 共同的保護

- 兩個入口各自有同時連線上限（預設與網頁一樣 200，可用設定調整），超過時回一行提示後斷線。
- 連不上遊戲伺服器時（例如伺服器重開中），回一行提示後斷線。
- 用設定開關：`ZMUD_PORT`、`TELNET_PORT` 設為 0 就不開該入口，出問題時可以單獨關掉。

### 4. 部署腳本

- `deploy/oracle/setup.sh`：主機防火牆開放 4002、4003。
- `deploy/oracle/update.sh`：已會在 `server/package.json` 變動時自動安裝套件，不需要改。
- `docs/DEPLOY_ORACLE.md`：補上 Oracle 安全清單開放 4002、4003 的步驟（要在 Oracle 網頁上手動操作）。

### 5. 玩家說明

- 寫一份連線說明：zMUD 與其他用戶端要填的主機位址、埠號、編碼設定。
- 是否放到登入畫面或網頁上，待確認（見第七節）。

### 6. Big5 字元檢查工具

- 新增 `tools/check_big5_text.py`：掃描遊戲程式裡給玩家看的文字，列出 Big5 沒有的字與所在檔案、行號。
- 第一次執行可能會找出目前已存在的字，結果列清單請使用者決定要不要改。
- 在 `CLAUDE.md` 補上製作內容時的相容原則（見第六節）。

## 五、不會改動的部分

- 遊戲本身的程式：戰鬥、技能、武功、NPC、指令都不動。
- 網頁玩家的連線方式與網頁介面。
- 遊戲伺服器 4001 的設定。

出問題時把 4002、4003 關掉（設定設為 0 或防火牆關閉），就回到現在的狀態。

## 六、之後製作內容要注意的事（寫進 CLAUDE.md）

1. **字元**：給玩家看的文字避免使用 Big5 沒有的字，例如表情符號、`▪`、`✦`、`➤`、簡體字與罕用字。
   常用的 `■ □ ★ ☆ ○ ● ◎ ※ →` 都可以用。改完內容跑一次字元檢查工具。
2. **顏色**：只用 mudlib 現成的 16 色代碼（`HIR`、`HIG`、`YEL` 等），不用 256 色。
3. **資訊要出現在遊戲文字裡**：網頁的地圖、角色狀態、聊天視窗只是額外整理；新功能不能只顯示在網頁面板。
4. **排版**：一個中文字等於兩個英文字寬，對齊畫面寬度不超過 80 格。

## 七、限制

- zMUD 玩家看到 Big5 沒有的字會是「?」。一般繁體中文不受影響；`score` 的 `■ □` 進度條在 zMUD 上正常顯示。
- telnet 與 zMUD 玩家沒有網頁的地圖、角色狀態、聊天視窗，用用戶端自己的觸發、計時器。
- telnet 是明碼傳輸，密碼沒有加密（傳統 MUD 都是如此）；網頁走 https 有加密。
- 同一個角色同時只能在一處登入，後登入的會接手連線（遊戲原本的規則）。
- 測試環境無法執行真正的 zMUD 4.62，只能用程式模擬 Big5 用戶端；上線後需要實際用 zMUD 連一次確認。

## 八、測試方式

1. 在本機架遊戲伺服器與橋接程式。
2. 模擬 Big5 用戶端連 4002：建角色、登入、`look`、`score`、`chat`，確認中文、顏色、`■ □` 進度條正常。
3. 模擬 UTF-8 用戶端連 4003：同上。
4. 網頁玩家與 zMUD 玩家同時在線：互相看得到、聊天互通、密語互通。
5. 一個中文字被切成兩段送達時，轉碼仍正確。
6. 超過連線上限、遊戲伺服器未啟動時，有提示且不當掉。
7. 網頁的既有測試結果不變。

## 九、上線步驟

1. 合併程式到 `main`，再合併到 wolfer168 的 `main`。
2. 在雲端主機執行 `bash ~/es2-webmud/deploy/oracle/update.sh`（會重開服務，線上玩家短暫斷線）。
3. 到 Oracle 主控台的安全清單開放 TCP 4002、4003（附步驟）。
4. 主機防火牆開放 4002、4003（重新執行 setup.sh 或照文件手動執行）。
5. 用 zMUD 連 `161.118.234.100`、埠 4002 實際測試。
