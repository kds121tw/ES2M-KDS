# 開 PR 時自動檢查（規劃）

對應 `docs/IMPROVEMENT_ROADMAP.md` 第 1 項。狀態：**已確認並完成**（2026-10-24）。使用說明見 `docs/CI_AUTO_CHECK.md`。

## 目標

每次開 PR（或 PR 有新的修改）時，GitHub 自動在一台臨時的雲端機器上：

1. 編譯遊戲伺服器；
2. 開機，確認遊戲能正常啟動；
3. 新建一個測試角色、登入一次、看一下狀態、離開；
4. 跑專案裡現有的測試。

任何一步失敗，PR 頁面會出現紅色叉叉，並且（開啟保護設定後）**不能按合併**。
全部通過才是綠色勾勾。

這台臨時機器用完就丟，跟 Oracle 正式主機完全無關，不會碰到玩家資料。

## 已在本機實際試過的結果

| 步驟 | 結果 | 花費時間 |
|---|---|---|
| 編譯遊戲伺服器（跟 `update.sh` 同樣的指令） | 成功 | 約 20 秒 |
| 開機到可以連線 | 成功 | 約 2 秒 |
| 新建角色（代號、密碼、電子郵件、人類、男性、名稱）→ 進到客棧大堂 → `score` → `quit` | 成功 | 約 15 秒 |
| 跑全部 123 個測試 | 120 個通過、3 個失敗（見下方） | 約 30 秒 |

整套檢查預估 **3 分鐘內**跑完（含 GitHub 準備機器的時間）。

試的過程中發現三個要注意的地方，規劃裡已經處理：

- 遊戲只接受 4001 這個連線埠（`neolith.conf` 的設定），換別的連線埠會被拒絕，所以檢查時照用 4001。
- 剛從 GitHub 拉下來的程式缺少存放玩家資料的資料夾，角色會存檔失敗。
  檢查時照 `deploy/oracle/setup.sh` 的做法先把資料夾建好（正式主機本來就有）。
- 有 5 個測試需要先安裝網頁橋接程式用的套件（`npm ci`），裝好之後都通過。

## 檢查流程細節

### 1. 編譯
跟正式主機一樣的指令：`cmake --preset linux`、`cmake --build --preset pr-linux --target neolith`。
`source/upstream/neolith/` 有語法錯誤就會在這一步失敗。

### 2. 開機
在臨時機器上啟動遊戲，等最多 60 秒看能不能連上 4001。
`master.c`、`simul_efun`、`preload` 列出的系統程式（logind 等）任何一個載入失敗，遊戲就開不起來或連不上，在這一步抓到。
開機過程的紀錄若出現載入錯誤（compile error），也判定失敗。

### 3. 登入一次
用一支小程式模擬玩家連線，照實際畫面一步步回答：

```
您的使用者代號：citest
...創造一個新的人物﹐您確定嗎？ y
請設定您的密碼／再輸入一次
您的電子郵件地址：none
選種族：human
性別：m
顯示名稱：測試
您確定要創造這個角色嗎？ y
→ 必須看到「冒險開始了」「目前權限」與房間敘述
score → 必須看到角色狀態
quit → 必須看到「歡迎下次再來」
```

接著**再用同一個角色登入一次**（輸入代號、密碼），確認舊角色也能讀檔進來。
這兩條路（新玩家、舊玩家）就是「全服登不進去」會壞掉的地方：`login.c`、`user.c`、`logind.c`、
角色、種族、出生房間有錯都會在這裡失敗。

每一步最多等 15 秒，等不到就失敗，並把最後收到的畫面印出來，方便看是哪裡卡住。

### 4. 網頁橋接程式
啟動 `server/index.js`，確認健康檢查網址有回應，確保 `server/` 改壞時也會被擋下。

### 5. 跑現有測試
`tests/` 裡的 `.py` 用 `python3` 跑、`.mjs` 用 `node` 跑，每個最多 5 分鐘。

## 要新增的檔案

| 檔案 | 用途 |
|---|---|
| `.github/workflows/pr-check.yml` | GitHub 自動檢查的設定：什麼時候跑、跑哪些步驟 |
| `tools/ci_boot_login.py` | 開機與模擬登入的小程式（第 2～4 步） |
| `tools/ci_run_tests.sh` | 逐一跑測試並套用「已知失敗」清單（第 5 步） |
| `docs/CI_AUTO_CHECK.md` | 完成後的使用說明：紅叉叉怎麼看、怎麼找原因（取代這份規劃） |

不會改動任何遊戲程式、測試內容或正式主機的腳本。

## 「有錯不准合併」要使用者在 GitHub 打開

自動檢查本身只會亮紅燈；要真的「不准合併」，必須由 repo 擁有者在 GitHub 打開保護設定
（Settings → Branches → 為 `main` 加規則 → 勾選「合併前必須通過檢查」，選 `pr-check`）。
這個設定 Claude 沒有權限改，做好後我會附上一步一步的截圖說明。

- `wolfer168/es2-webmud`（路線圖第 9 項完成後，PR 一律開在這裡）：檢查設定檔合併後就會自動跑，
  但「不准合併」要 wolfer168 本人設定。其他協作者在 wolfer168 開的 PR 也會被檢查到。

另外，`CLAUDE.md`「開 PR」流程目前是開完直接合併；之後改成**等檢查變綠燈才合併**，紅燈就先修好（**待確認 3**）。

## 這次先不做、之後可加

- **把所有房間、NPC、武功檔都載入一次**：可以抓到登入不會碰到的檔案語法錯誤（例如某個偏遠房間），
  但檔案數量多、可能先冒出一堆舊錯誤，要另外整理。建議等這版穩定後再加（**待確認 2**）。
- 路線圖第 14、15 項（遊戲文字、說明檔格式的自動檢查）之後可以掛在同一套流程裡。
